# MotionBricks traversal architecture

The test uses an offline SOMA export. NVIDIA's runtime generates the motion with TensorRT on the L4. Unreal plays a native `UAnimSequence` and sweeps the capsule along the same sampled trajectory. The runtime module needs no model, inference service, or network connection.

1. `tools/motionbricks/generate_traversal.py` uses NVIDIA's Smart Primitive loader and SOMA engine. The authored entry window seeds context. The engine generates toward the action and exit targets. The exporter chains from the last four played frames, removes the duplicate segment boundary, and validates finite local transforms, normalized quaternions and contact values. It exports 30 Hz transforms in Unreal coordinates and centimeters, converting rotations by conjugating with the same basis change as the positions.
2. `MotionBricksTraversalEditor` converts SOMA joint rotations to the target mesh using world rotation offsets from the aligned bind poses. It keeps the target bone lengths and maps the purchased soldier's three spine bones separately from the mannequins' five. Matching source and target limb directions compensates for differences in bind pose while retaining twist. The importer accounts for the mesh's −90° relative yaw and for the SOMA bind pose facing away from the traversal direction. It writes animation tracks with Unreal's animation data controller and bakes the foot IK helpers to follow the animated ankles. The hips' translation over time is stored in a companion data asset and scaled to target stature.
3. On **E**, the test character calls the shared component. It checks facing, distance, lateral position, ground and landing volume, sweeps the recorded path with a shorter capsule, aligns to the center of the marked region, and pauses character movement simulation while traversal owns the capsule. It samples a montage and the root curve with one clock. The montage blends in over 90 ms and out over 120 ms. The mannequins use their locomotion Blueprint's `DefaultSlot`. The purchased rig's evaluation animation instance supplies the same slot over its idle and walk clips. The component sweeps at substeps, restores the standing capsule and walking movement when done, and attempts to return to the approach on an interruption.
4. `build_test_map.py` writes the map and imported data under `/Game/Developers/MotionBricksEvaluation`. The importer refuses existing output. `prepare_test_host.ps1` makes a small Unreal project with the plugin and mannequin assets and can copy the purchased packs into that host. The full game baseline build is documented in TEST_RESULTS.md.

For the 41-frame `OneHandedJump0` vault, `MBContactBake` uses two-bone IK to anchor the left palm and the two landing steps to this course. The torso leans just far enough to put the wall within arm reach. The solver preserves limb lengths and the generated bend directions, and fades the corrections around each plant. The foot helpers follow the corrected ankles. Each sequence uses its own target mesh as the retarget source so playback and the bake use the same reference proportions. The last four frames ease the vertical trajectory into the standing capsule height.

The anchors are authored for the evaluation wall and baked separately for each rig. For other sequences the importer uses its rotation retarget. The reduced movement capsule tests collision along the route. Hand and foot contact checks measure bone-local palm and sole points relative to the course surfaces and their anchors.

`UMBTraversalComponent::TryStart` takes a compatible clip and the caller's wall, landing surface and course frame. It reports completion or interruption. A player controller or AI can call the same Blueprint or C++ entry point. The current clips expect an upright, flat course and a matching mesh. Player input, rig selection, debug markers and equipment stay in the test harness. The licensed musket is attached to the chest as a slung prop, and the harness sweeps a volume based on its bounds against the course. Production deployment still needs a transition from the game's held weapon poses and multiplayer authority handling.

The SOMA FP32 model was inspected with ONNX. It uses standard-domain opset 17 including LayerNormalization, ScatterND, ScatterElements, Resize, Range, TopK and shape operations. No custom operator domain was present. The installed Unreal ORT plugin advertises DirectML on D3D12. That is a candidate for a separate import, exact tensor parity and latency test. Successful TensorRT inference on this VM does not establish Unreal NNE operator coverage or the cost of moving control and poses between game, CPU and GPU. A future live backend must work asynchronously, keep an ordinary locomotion fallback, and handle stale results. No live backend was selected for this prototype.

The MotionBricks source is Apache 2.0, NVIDIA's ONNX model has a separate Open Model Agreement, and the bundled Bones-derived motion samples have their own internal evaluation terms. Keep the generated evaluation animation and related captures local. A production pass should use authorized conditioning data, retarget and validate the licensed soldier with its equipment, and add a contact solution, interruption handling and multiplayer authority checks as needed.
